PAGINA DE ESCANDALO — COMO USARLA
==================================

Abrir en la compu: node scripts/servir.js y entrar a http://localhost:8080
(las páginas usan URLs limpias: /galeria, /calendario, /historia; no funcionan con doble clic en el .html)

DONDE SUBIR LAS FOTOS (carpeta assets/)
---------------------------------------
assets/logos/logo.png        -> logo chico (bomba) para menu y footer
assets/logos/logo-full.png   -> logo completo con texto, portada
assets/logos/_originales/    -> archivos originales del zip
assets/hero/hero.jpg         -> foto grande de portada (horizontal, idealmente 1920px de ancho)
assets/jugadores/            -> una foto por jugador (vertical, tipo 3:4). Nombre = el que pusiste en js/data.js
assets/torneo/             -> fotos y videos de la galería (se listan en js/data.js, GALERIA)

EDITAR TEXTOS, JUGADORES, PARTIDOS Y RESULTADOS
-----------------------------------------------
Todo esta en js/data.js. Cambia los nombres, fechas, numero de WhatsApp, mail, etc.
Si una foto no existe, la pagina muestra un reemplazo automaticamente (no se rompe).

COLORES
-------
Estan al principio de css/style.css (--a rosa, --b lima). Se pueden cambiar por los colores del logo.

AGREGAR UN JUGADOR
------------------
1. Su carta en assets/jugadores/<nombre-apellido>.webp (720x1280)
2. La misma carta en JPG en assets/jugadores/compartir/<nombre-apellido>.jpg (para compartir/descargar)
3. Sus datos en JUGADORES, en js/data.js
4. node scripts/jugadores.js  (genera su link para compartir: /jugador/<nombre-apellido>)

BASE DE DATOS LOCAL (Supabase)
------------------------------
Requiere Docker Desktop abierto.
  npx supabase start       -> levanta la base (la 1ª vez descarga imágenes)
  npx supabase stop        -> la apaga
  npx supabase db reset    -> la borra y la recrea SOLO con las migraciones (estructura + datos públicos iniciales)
                              después hay que volver a correr: node scripts/crear-usuarios.js  y  python scripts/importar_asistencia.py
Panel visual (Studio): http://127.0.0.1:54323     API: http://127.0.0.1:54321
Consultas SQL: Studio -> SQL Editor, o:  docker exec -it supabase_db_escandalo psql -U postgres

QUE DATOS USA EL SITIO
----------------------
En localhost: lee jugadores, torneos y partidos de la base local (si está prendida).
Si la base no responde: usa la última copia guardada en el navegador, y si no hay, js/data.js.
En escandaloultimate.com: usa js/data.js (todavía no hay base real). Se configura en js/config.js.
Los textos de Nosotros, los hitos y la galería siguen en js/data.js.

ROLES Y PANEL DE ADMINISTRACION (solo en local por ahora)
---------------------------------------------------------
Rol admin: Juan Jose Alonso (definido en ADMINS de scripts/crear-usuarios.js). El resto: rol usuario.
Al loguearse, arriba a la derecha aparece su nombre con un menú: Panel de administración (solo admin) y Cerrar sesión.
Panel: /admin. Hoy gestiona jugadores (agregar, editar, ocultar, eliminar). Torneos y partidos vienen después.
Los permisos los hace cumplir la base (reglas de seguridad por filas): un usuario común no puede modificar nada aunque abra /admin.
Un jugador nuevo creado desde el panel necesita su imagen en assets/jugadores/ y, para poder loguearse, un usuario
(node scripts/crear-usuarios.js lo crea). Después de `npx supabase migration up` o `db reset`, correr ese script.

ASISTENCIA A PRACTICAS (solo en local por ahora)
------------------------------------------------
Página para jugadores con sesión (solo ver): /asistencia. Para el admin: /admin#asistencia (agregar, editar y borrar prácticas).
Caja del equipo (ingresos/egresos/balance): /caja — la ven todos los logueados; solo un admin carga montos.
Cada práctica guarda quién fue, quién faltó y a quién no le contaba (todavía no estaba en el equipo): por eso un jugador nuevo
tiene 100% con su primera práctica. El porcentaje es "fue / prácticas que contaban para esa persona".
Importar el Excel (una vez): ponerlo en supabase/privado/Asistencia a practicas.xlsx y correr
   python scripts/importar_asistencia.py            (--reemplazar para volver a cargar)
IMPORTANTE: el repositorio es público. La asistencia de cada persona NO se sube: el Excel y supabase/privado/ están ignorados por Git.

PASAR A PRODUCCION (proyecto Supabase: efdlvrznaqbijyftwzgf.supabase.co)
------------------------------------------------------------------------
1. En el panel de Supabase: Authentication → Sign In / Providers → apagar "Allow new users to sign up" (el registro abierto
   permite que cualquiera se cree una cuenta) y subir la longitud mínima de contraseña (Authentication → Sign In / Providers → Email).
2. Estructura:    npx supabase login  ·  npx supabase link --project-ref efdlvrznaqbijyftwzgf
                  npx supabase db push --dry-run   ·   npx supabase db push
3. Usuarios con contraseñas reales:    node scripts/usuarios-produccion.js   (pide la clave secreta service_role sin mostrarla)
4. Asistencia:    python scripts/importar_asistencia.py --produccion
5. Recién ahí, publicar la rama conexion_produccion (js/config.js ya apunta al proyecto cuando el sitio se abre en escandaloultimate.com).
La clave secreta (service_role) y la contraseña de la base NUNCA van al repositorio ni al chat.
MIGRACIONES: COMO SE MANEJA LA BASE (LOCAL Y PRODUCCION)
--------------------------------------------------------
supabase/migrations/ es la fuente de verdad: local y producción aplican los mismos archivos, en el mismo orden.
  - Estructura (tablas, reglas, funciones): siempre una migración nueva. NUNCA editar una ya aplicada.
  - Datos públicos fijos de arranque: migración de datos iniciales (sin duplicar: on conflict do nothing).
  - Datos que cambian (jugadores, resultados, prácticas): panel de administración.
  - Datos PRIVADOS (asistencia) y contraseñas: nunca en migraciones (el repositorio es público). Van por scripts.
  - No tocar la estructura a mano en el panel web de Supabase: se pierde la igualdad con local.
Nueva migración:   npx supabase migration new nombre_del_cambio   (se escribe el SQL y se prueba con: npx supabase migration up)
Ver diferencias:   npx supabase migration list      |      npx supabase db diff --linked
Subir a producción (proyecto ya vinculado):   npx supabase db push --dry-run   y luego   npx supabase db push
